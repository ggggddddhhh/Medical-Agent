# 医疗安全智能体产品设计文档（MVP）

## 1. 产品概述

本产品是一款面向成年人的、限定症状范围的安全分诊与就医准备智能体。它通过多轮追问、协议化知识、工具调用和安全策略，帮助用户判断下一步应采取的行动。

产品不以诊断疾病为目标，核心回答的是：

> 根据当前信息，用户应该立即急救、当天就医、近期门诊、暂时观察，还是因为信息不足而咨询医疗专业人员。

MVP 首要验证三个能力：危险情况不漏报、只询问必要信息、无法安全判断时主动退出。

## 2. 目标用户与使用场景

### 目标用户

- 已满 18 周岁的普通用户
- 希望了解症状处置紧急程度和就医科室的用户
- 在正式就医前需要整理症状与危险信号的用户

### 典型场景

- 用户描述头痛或胸痛，智能体动态追问关键症状。
- 发现危险信号后立即停止普通问答，并给出急救指引。
- 未发现紧急信号时，给出当天就医、近期门诊或暂时观察建议。
- 用户提出超出范围的问题时，明确说明能力边界并建议咨询专业人员。

## 3. MVP 范围

第一版仅支持两条经过版本管理的症状路径：

- 头痛：`HEADACHE_V1`
- 胸痛：`CHEST_PAIN_V1`

第一版暂不支持儿童问诊、疾病诊断、处方和个性化药物剂量、检验或影像解读、长期病史管理、慢病治疗方案、心理治疗以及开放式互联网医学检索。

## 4. 产品设计原则

1. **处置优先**：输出行动建议，不输出疾病结论。
2. **安全优先**：危险信号可以提前终止普通追问，宁可保守升级。
3. **最少必要信息**：只采集当前症状路径需要的信息。
4. **有限自主**：智能体只能在预定义动作和白名单工具中决策。
5. **协议驱动**：医学内容来自经过审核和版本管理的症状协议。
6. **可追溯**：记录结构化决策轨迹，不记录隐藏思维链。

## 5. 主要功能

| 功能 | 说明 |
| --- | --- |
| AI 身份与能力说明 | 明确告知用户正在与 AI 交互，输出不是诊断或处方 |
| 范围识别 | 判断是否为成年人、是否属于当前支持的症状路径 |
| Case State | 在当前会话中维护症状、危险信号、相关病史和决策状态 |
| 动态多轮追问 | 每轮选择当前最有价值的一项问题，避免一次收集完整病史 |
| Red Flag 识别 | 结合确定性规则和语义标准化识别急症、自伤等危险信号 |
| Agent Action | 在追问、工具调用、处置输出、安全升级、越界退出和信息不足之间决策 |
| 处置紧急程度 | 输出立即急救、当天就医、近期门诊、暂时观察或信息不足 |
| 白名单工具 | 查询临床协议、推荐就诊科室、返回部署地区急救资源 |
| Safety Gate | 拦截诊断式结论、个性化剂量、矛盾急救建议和提示词注入 |
| Decision Trace | 记录规则命中、动作、工具、处置结果及协议和策略版本 |

## 6. 核心流程

```text
用户描述症状
    ↓
输入安全检查：急症、自伤、注入和用药边界
    ↓
识别支持范围并更新 Case State
    ↓
加载对应症状协议
    ↓
Clinical Policy Engine 决定下一步动作
    ├─ ASK_MORE：追问一项关键信息
    ├─ CALL_TOOL：调用只读白名单工具
    ├─ SAFETY_ESCALATION：停止追问并升级
    ├─ OUT_OF_SCOPE：说明产品边界
    └─ DISPOSITION：输出处置紧急程度
    ↓
输出安全检查
    ↓
用户回答 + Decision Trace
```

## 7. 处置与智能体状态

智能体动作包括：

- `ASK_MORE`
- `CALL_TOOL`
- `DISPOSITION`
- `SAFETY_ESCALATION`
- `OUT_OF_SCOPE`
- `INSUFFICIENT_INFO`

处置紧急程度包括：

- `EMERGENCY_NOW`：立即联系急救服务或前往急诊
- `URGENT_SAME_DAY`：建议当天由医疗专业人员评估
- `CLINIC_SOON`：建议近期安排门诊
- `SELF_MONITOR`：当前可暂时观察，并展示升级条件
- `INSUFFICIENT_INFORMATION`：信息不足，无法安全判断

## 8. 安全与数据设计

- 急症策略由独立安全规则控制，聊天模型不能自行降低紧急程度。
- 自伤识别属于基础安全能力，但产品不提供心理治疗服务。
- 工具仅允许只读调用，执行预约、支付、发送消息或写入病历必须留到后续版本，并增加用户确认。
- 医疗健康信息按敏感信息处理，遵循明确目的、最少采集、访问控制和可删除原则。
- 审计日志只保留结构化状态、规则和版本信息，避免保存不必要的原始对话。
- 工具不可用或协议缺失时进行安全降级，不由模型补造医学结论。

## 9. 输出结构

面向用户的结果应保持简洁，并包含：

- AI 身份与医疗边界提示
- 当前处置紧急程度
- 触发该处置的可解释原因
- 现在应该采取的行动
- 症状恶化时需要关注的危险信号
- 必要时的就诊科室或急救资源

## 10. MVP 验收方向

- 经过临床审核的哨兵急症测试不得漏掉安全升级。
- 当前确定性词表覆盖范围内的危险信号改写应得到一致处置；更广泛的错别字、方言、口语和隐含表达需要在 LLM Semantic Extraction 阶段单独验证。
- 智能体不得调用白名单之外的工具。
- 工具失败时不得生成虚假医学信息。
- 不得输出疾病确诊、个性化药物剂量或与紧急等级矛盾的建议。
- 所有协议、策略和安全规则更新必须通过完整回归测试。

## 11. 后续迭代

### P1

- 扩展到 5～8 个限定症状路径
- 医院和门诊搜索、预约前确认
- 经过审核的患者健康教育内容
- 经过严格边界控制的药品说明书查询
- 接入 LLM 进行病例结构化和问题排序，同时保留确定性安全策略

### P2

- 检验报告和医学影像辅助理解
- 患者授权下的长期健康记录
- 慢病管理与医护人员协作
- 更复杂的临床决策支持能力

以上能力需要重新进行临床、安全、隐私和医疗器械监管评估，不直接沿用 MVP 的风险结论。
